# §1+§2+§10 目标 / 约束 / 质量需求

## 目标（Goal）

1. 让服务器管理员**不用进游戏**，就能在外置 GUI 里圈选任意区块范围，并对其施加「防放置」或「防方块更新」保护，保护即时生效、可灰度启停。
2. 地图底图直接复用手上已有的 **Xaero 世界地图数据**，避免单独维护一份区块地理数据；支持百万区块级大图。
3. 交付物能**原样部署到甲方 NeoForge 服务器**，本地 PCL2（MC 1.21.1 / NF 21.1.219 / KubeJS 2101.7.2）用于开发验证。

## 约束（Constraint）

| 类别 | 内容 |
|---|---|
| 技术 | 服务端逻辑**只用 KubeJS 脚本**（不允许改 MC/其他 mod 源码）；GUI 用 **C# / .NET 8 WPF** |
| 版本 | MC 1.21.1 / NeoForge 21.1.219 / KubeJS 2101.7.2（锁定，避免环境漂移） |
| 数据交换 | GUI ⇄ KubeJS 之间**仅通过 `kubejs/config/regions.json`** 交换（写文件 + 定时/`/reload` 热读） |
| 协作 | 由 AI agent + 少量人工维护；遵循 arc42lite 文档规范 |

## 质量需求（Quality — 以场景表达）

1. **加载性能**：当管理员打开 GUI 面对一个**百万区块**的服务器世界时，系统应**只加载当前视口所需的地图 tile（LOD 惰性）**，以便首屏在 <300ms 内可交互、缩放平移不卡顿。
2. **拦截性能**：当玩家在保护区内放置方块、或区域内发生方块更新时，系统应**以 O(1) 判定是否命中保护再决定拦截**，以便在高密度服务器上对正常游戏几乎无感知（单次判定开销 < 微秒级）。
3. **生效及时性**：当管理员在 GUI 保存/切换一个选区后，该变更应**在 ≤ 若干 tick 内被服务器读取并生效**（不必重启、不必玩家重进）。
4. **可复现部署**：当在任意一台**新鲜的 NeoForge 专用服务器**上操作时，系统应能**仅复制 `kubejs-scripts/` + `config-schema/` 即可用**，以便甲方部署零环境假设。
5. **配置一致性**：当 `regions.json` 由 GUI 写出时，其内容应**始终符合 `config-schema/regions.schema.json`**，以便脚本读取不因坏配置崩溃。

## 横切概念（Cross-cutting）

- **坐标系**：保护范围一律用**区块坐标**（`chunkX/chunkZ`，1 区块 = 16×16 方块），维度独立。GUI 在地图上方叠加区块网格，选区用区块矩形表示。
- **性能策略**：命中判定 = 方块坐标 → 整除 16 得区块 → 查内存中预构建的 HashMap<dim, HashMap<chunkKey, mode>>。
- **配置协议**：单一 JSON 契约（见 `config-schema/`），GUI 与脚本两端的读/写以此为唯一真相源。
