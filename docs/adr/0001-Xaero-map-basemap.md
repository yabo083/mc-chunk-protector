# ADR-0001: 地图底图方案 —— 探索网格为主，Xaero 真实渲染为可选增强

## 日期
2026-02-16

## 状态
accepted

## 背景
GUI 需要一张世界地图底图来定位/框选服务器区块，目标服务器的 Xaero 缓存可能达到**百万区块级**。
我们调研了 Xaero 世界地图数据格式（详见 `docs/data/xaero-format-notes.md` 与子代理报告）：

- `{x}_{z}.zip` 内是单个 `region.xaero`，一种 **deflate 压缩、单一缩放、自描述字节格式**（32×32 区块，512×512px，1px=1 方块），内嵌 NBT 方块状态调色板 + 生物群系 + 光照。
- 磁盘上**没有**既成的 LOD/mipmap 多层缩放，高倍放大与全景 LOD 需运行时自建金字塔。
- 有成熟 C++ 参考实现 [DanDucky/XaerosMapFormat](https://github.com/DanDucky/XaerosMapFormat)；无现成 C# 解析库，原生移植需实现大端 bit-reader、NBT 解码（fNbt）、方块/生物群系色表生成，工作量大。

## 决策
**以「探索网格」作为默认/首版底图渲染**：只读 `{x}_{z}.zip` 的**存在性** = 该 region 已被玩家探索，按区块网格上色。真实地形渲染（真正解析 region.xaero）作为**可选增强**（`BaseMap` 下拉切换），参考 DanDucky 或 C++ 批转 PNG 接入。

## 后果
- 正面：零字节解析、IO 极轻（仅列目录+文件存在性）；对百万 tile 天然惰性、几乎即时；底图需求（定位/框选/看探索范围）完全满足。
- 负面 / 代价：看不到真实地形、河流/山脉/建筑纹理，只有"已探索区域"色块叠加查询网格。

## 备选方案（关键）
- **原生 C# 移植 region.xaero 解析**（fNbt + 自写 bit-reader + 色表）：能出真实细腻底图，但工作量大、易与 mod 自定义方块色表失配 → **为何放弃**：首版不必要，且"探索网格"已满足核心功能；留作 v2 可选增强，参考实现已就绪。
- **C++ 转换器批转 PNG 分块**（调 DanDucky）：能快速出真图，但引入 C++/CMake 构建链到 WPF 工程，复杂度和分发体积上升 → **为何放弃**：为可选能力引入第二构建工具链不划算。
